# ArthurTech: Таблица перевода v3 — Дихотомия Пота и Угара
### (адаптация под шаблон `skuf-addon`)

> **Статус:** рабочий инженерный документ.  
> **Роль:** мост между `arthur_core.md` и будущим `arthurtech_design_bible.md`.  
> **Задача:** перевести философские концепции Артура в конкретные сущности GregTech-аддона: механики, материалы, жидкости, машины, мультиблоки, квесты, тира и MVP-приоритеты.  
> **Принцип:** не «мем → предмет», а **философский принцип → функция в прогрессии → игровая сущность**.

> **Адаптация под `skuf-addon`:** этот документ переписан под реальный технический базис — **`skuf-addon`** (GregTech Addon Template, Forge 1.20.1, GTCEu 7.4.0, Registrate). Это **чистый Java-аддон без KubeJS**. Поэтому все сущности привязаны к Java-регистрации через хуки шаблона (`SkufMaterials`, `SkufRecipeTypes`, `SkufMachines`, `SkufItems`, `SkufBlocks`, `SkufRecipes`, `SkufElements` и хуки `IGTAddon`). Изначальный план v3 предполагал «KubeJS-first»; здесь это заменено на Java + GTCEu API. Содержание, философия, баланс и прогрессия сохранены полностью.

> **Русификация v3:** все пользовательские названия предметов, машин, механик и квестовых сущностей переведены на русский. Английские названия модов и API (GregTech, GTCEu, Monifactory, AE2, Registrate) оставлены как есть. Английские `resource_id` сохранены в латинице, потому что Minecraft/GTCEu требуют стабильные латинские идентификаторы. **Пространство имён изменено с `arthurtech:` на `skufaddon:`** (это `mod_id` шаблона), а ID материалов приведены к конвенции GTCEu (см. §9).

## Журнал изменений v2

В эту версию добавлен модуль **Дихотомия Пота и Угара**.

Новый слой документа описывает, как философские категории **«Не потеем»**, **«Ваще похуй»**, **«Горящий пукан»**, **«Разбор геймплея»**, **«Сауна Егора»** и **«Деревенский Покой»** переводятся в GregTech/Monifactory-подобную фабричную механику.

Ключевой сдвиг: завод теперь управляется не только энергией, материалами и рецептами, но и эмоционально-термодинамическим балансом:

```text
Пот ↔ Угар
↓
Скрытый разгон
↓
Тильт
↓
Аварийное игнорирование
↓
Катастрофа / охлаждение / деревенский покой
```

> **Журнал изменений v3 (адаптация под `skuf-addon`):** способ реализации переведён с KubeJS на Java-аддон. Сопоставлены уже заведённые в шаблоне материалы (`skufit`, `pokhuit`, `sweat`, `puff_smoke`), namespace переведён на `skufaddon:`, ID материалов приведены к системе материалов GTCEu (форма ingot/dust/plate/fluid генерируется флагами материала, а не отдельным item-ID).

## 0. Главная формула перевода

```text
Философия Артура
↓
Игровой принцип
↓
Механика / параметр
↓
Материал / жидкость / компонент
↓
Машина / мультиблок
↓
Квест / глава квестбука
↓
GregTech-тир
↓
MVP или поздняя игра
```

**ArthurTech не должен быть просто набором локальных шуток.**  
Он должен ощущаться как GregTech-аддон, где каждый мем становится частью производственной цепочки.

**Технический контур перевода под `skuf-addon`:**

```text
Концепция документа
↓
Хук регистрации в skuf-addon
↓
  • Материал  → SkufMaterials.init()            (хук addMaterials)
  • Элемент   → SkufElements.init()              (хук registerElements)
  • Тип рец.  → SkufRecipeTypes.init()           (хук registerRecipeTypes)
  • Машина    → SkufMachines.init()              (хук registerMachines)
  • Мультиблок→ SKUF_REGISTRATE.multiblock(...)  (класс в machine/multiblock/)
  • Предмет   → SkufItems.init()                 (Registrate item)
  • Блок      → SkufBlocks.init()                (Registrate block)
  • Рецепт    → SkufRecipes.init(provider)       (хук addRecipes)
  • Механика  → MachineTrait / SavedData / Forge-события / mixin
  • Звук      → SkufSounds.init()                (хук registerSounds)
  • Квест     → датапак FTB Quests (вне аддона)
↓
GregTech-тир + MVP/поздняя игра
```

### 1.1. Monifactory как дизайн-референс (не как структура кода)

Monifactory полезен **не как источник лора и не как структура кода**, а как **дизайн-эталон современного GregTech-модпака**. Структуру кода даёт шаблон `skuf-addon`, а Monifactory остаётся ориентиром по ощущению прогрессии.

#### Что берём как дизайн-референс

| Элемент Monifactory | Что это даёт ArthurTech | Как переводим (в Java-аддоне) |
|---|---|---|
| Современное переосмысление Nomifactory CEu | Можно переосмыслить старую формулу под свой вайб | ArthurTech = приватная реимагинация GT-прогрессии через философию Артура |
| Категории Квесты / Техника / Мультиплеер | Упор на квесты, завод и игру группой | Квестбук — датапак FTB Quests; завод — аддон; кооперация — желательна |
| Новые мультиблоки, моды, прогрессия | Не бояться кастомных мультиблоков | Челябинский Провал, Фабрика Правильных Вещей, Матрица Похуизма — классы в `machine/multiblock/` |
| Паровая эпоха в сложном режиме | Ранний этап грязный и ручной | «Грязный двор» как Паровая эпоха с ручной переработкой жижняка |
| Усложнённые цепочки переработки | Длинные цепочки — норма GT | Уральский изотоп и Правильная материя имеют длинные цепочки рецептов |
| Фокус на GregTech-энергетике | Энергия = GregTech-ядро | Похуистический генератор, Жижняковый котёл, Антинормисный реактор |
| Экспертный режим: RF→EU отключён | Нельзя обходить философию сторонней энергией | ArthurTech Эксперт: только EU |
| Взрывы машин в стиле GT5u | Поломки — часть характера | Нормисная энтропия и Разрабские схемы могут взрывать машины |
| GregTech-опасности | Опасности системны | Уральская радиация (через `radioactiveHazard`/Hazard Zones GTCEu), жижняковое загрязнение |
| Каналы AE2 включены | Логистика требует структуры | ДС/RTC-сеть как лорная обвязка каналов |
| Замена Draconic/Avaritia на скалк-механики | Поздняя игра вокруг новой материи | Нормисная сингулярность, Вайб-скалк, Абсолютный Похуит |
| Опциональная совместимость Create / XNet | Совместимость дополнительная | Create = эстетика ЧПУ; XNet = ДС/каналы |

#### Что не копировать напрямую

- Не копировать Monifactory как структуру глав один-в-один.
- Не делать «ещё один Nomifactory с мемными названиями».
- Не превращать Monicoins/магазин в главную экономику. **Правильные Вещи** — это ресурс истины и пропускная прогрессия, а не валюта магазина.
- Не подменять GregTech-фабрику декоративным лором. Сначала производственная цепочка (Java-рецепты), потом мем.

## 2. Уровни приоритета

| Приоритет | Значение |
|---|---|
| **MVP** | Должно войти в первую играбельную версию |
| **Ранняя версия** | Желательно в ранней версии, но можно после MVP |
| **Средняя версия** | Средняя прогрессия, MV/HV |
| **Поздняя игра** | EV/IV+, эндгейм |
| **Лор/флейвор** | Лор, НПС, шутки, косметика; не блокирует прогрессию |
| **Только приватная версия** | Можно использовать в приватной сборке для друзей, но лучше переименовать для публичного релиза |

## 4. MVP-концепции

В первую версию должны попасть только те идеи, которые создают **игровой цикл**, а не просто украшают сборку.

### 4.1. Семь обязательных MVP-концепций

| Концепция | Почему входит в MVP | Минимальная реализация в `skuf-addon` |
|---|---|---|
| Правильные Вещи | Главная цель, без неё нет смысла | 1 `SkufItems` item + 1 рецепт + квест-gate датапака |
| Жижняк | Базовая материя мира | `SkufMaterials` fluid + ручная добыча + тип рецепта «фильтр» |
| Нормисность | Главный враг/энтропия | `normie_dust` + per-chunk счётчик (SavedData) |
| Вайб | Позитивная противоположность энтропии | `stabilized_vibe` fluid + `recipeModifier` машины |
| Похуизм | Устойчивость к хаосу | `pokhuit` ✅ + модификатор корпуса машины |
| ЧПУ-станкчанин | Индустриальная честность | LV-машина (`registerSimpleMachines`) для точных деталей |
| Челябинская мутантность | Локальный ресурсный стиль | руда/`ural_isotope` + структура/биом (датапак) |

### 4.2. Минимальный игровой цикл MVP

```text
Камень / мусор / заражённая земля
↓
Ручная дробилка
↓
Жижняк + Нормисная пыль
↓
Нормисный фильтр
↓
Очищенный жижняк + Скуфитовый остаток
↓
Пар/LV machines
↓
ЧПУ-станкчанин
↓
Похуитовые детали
↓
Правильная материя
↓
Первая Правильная Вещь
```

### 4.3. MVP-материалы

> В GTCEu материал заводится один раз (`new Material.Builder(SkufAddon.id("name"))…`), а формы (ingot/dust/plate/fluid) включаются флагами. Поэтому колонка «ID» — это имя материала, а «Тип» — нужная форма.

| Материал (`skufaddon:`) | Название | Форма | Назначение | Рецептурная роль |
|---|---|---|---|---|
| `jizhnyak` | Жижняк | fluid | Базовая жидкость хаоса | Вход в фильтры, котлы, дистилляторы |
| `normie_dust` | Нормисная пыль | dust | Загрязнение и компонент | Поднимает энтропию, дешёвые рецепты |
| `skufit` ✅ | Скуфит | ingot | Ранний грязный металл | Корпуса Пар/LV |
| `pokhuit` ✅ | Похуит | ingot | Стабильный сплав | Провода, корпуса, генераторы |
| `correct_matter` | Правильная материя | gem | Предфинальный смысловой ресурс | Крафт Правильной Вещи |
| `ural_isotope` | Уральский изотоп | dust (radioactive) | Мутантный ресурс | HV/EV processing |
| (item) `item_pravilnaya_vesh` | Правильная Вещь | Registrate item | Gate-прогрессия | Открытие главы MV/HV |

### 4.4. MVP-машины

| Машина | Тир | Реализация | Вход | Выход | Зачем нужна |
|---|---|---|---|---|---|
| Ручная Дробилка Жижняка | Пар/ручная | тип рецепта + простая машина | Камень, dirt, мусор | Жижняк, Нормисная пыль | Начало цикла |
| Котёл Втыкания | Пар | тип рецепта-генератора | Вода, уголь, жижняк | Пар, Грязная мысль | Ранняя энергия + лор |
| Нормисный Фильтр | Пар/LV | `SkufRecipeTypes.NORMIE_FILTER` + `registerSimpleMachines` | Жижняк + фильтр | Очищенный жижняк + отходы | Контроль энтропии |
| Примитивный ЧПУ-стол / ЧПУ-станкчанин | LV | `SkufRecipeTypes.CNC_MACHINING` | Скуфит/Похуит | Детали, пластины | Первая честная точность |
| Дистиллятор Правильной Материи | MV | тип рецепта `CORRECT_DISTILLER` | Очищенный жижняк + вайб | Правильная материя | Переход к ядровому ресурсу |
| Мини-Фабрика Правильных Вещей | MV | мультиблок (`SKUF_REGISTRATE.multiblock`) | Правильная материя + Похуит | Правильная Вещь | Первый большой рубеж |

## 8. Конкретные рецептурные цепочки

> В `skuf-addon` цепочки пишутся в `SkufRecipes.init(provider)` (хук `addRecipes`), через builder-ы типов рецептов из `SkufRecipeTypes` (например `SkufRecipeTypes.NORMIE_FILTER.recipeBuilder(...).inputFluids(...).outputItems(...).save(provider)`).

### 8.1. Жижняк → Правильная материя

```text
Заражённая земля / мусор / камень
  → Ручная Дробилка
  → Жижняк + Нормисная пыль
  → Нормисный Фильтр
  → Очищенный Жижняк + Нормисный Осадок
  → Дистиллятор Правильной Материи
  → Правильная Материя
  → Мини-Фабрика Правильных Вещей
  → Правильная Вещь
```

**Философский смысл:** из мутной первоматерии через фильтрацию и работу рождается интуитивная истина.

### 8.2. Скуфит → Похуит

```text
Нормисная пыль + Железо + Челябинский шлак
  → Скуфитовая смесь
  → Скуфитовый слиток (skufaddon:skufit ✅)
  → Похуистическая обработка стабилизированным вайбом
  → Похуит (skufaddon:pokhuit ✅)
  → Похуитовые провода / корпуса / генераторы
```

**Философский смысл:** деградацию можно переплавить в устойчивость.  
**Заметка по реализации:** оба слитка уже заведены в шаблоне — нужно лишь описать рецепт сплава и формы (`wireGtSingle`, `casing`) флагами материала `pokhuit`.

### 8.3. Разрабские схемы

```text
Пластина правильной мысли
  + Меметический сплав
  + Похуитовый провод
  + Колхозный резистор
  → Нестабильная разрабская схема
  → Стабилизация Вайбом
  → Правильная разрабская схема
```

**Философский смысл:** разрабская неоднозначность сначала нестабильна, но может стать силой прогрессии.

### 8.4. Челябинский Провал

```text
Плотная жижа + Челябинский шлак + Нормисный осадок
  → Челябинский Провал (мультиблок)
  → Уральский изотоп + мутантные побочки + асфальтовые трещины
```

**Философский смысл:** региональная мутантность опасна, но именно она даёт редкие ресурсы.

### 8.5. Абсолютный Похуизм

```text
Правильная Вещь
  + Уральский изотоп
  + Антизумерное ядро
  + Стабилизированный вайб
  + Правильная разрабская схема
  → Абсолютный Похуит
```

**Философский смысл:** высшая устойчивость рождается из истины, региона, вайба и технической неоднозначности.

## 9. Предметные ID и правила именования (конвенция `skuf-addon`)

### 9.1. Пространство имён и две системы ID

`mod_id` шаблона — `skufaddon`. В GTCEu различаются **GT-материалы** и **обычные предметы/блоки Registrate**:

```text
GT-материал:                skufaddon:<name>           (формы ingot/dust/plate/fluid — через флаги)
Обычный предмет/блок:       skufaddon:<category>_<name> (через Registrate: item/block)
```

То есть `arthurtech:ingot_skufit` из v3 превращается в **материал** `skufaddon:skufit` с флагом, генерирующим слиток; отдельный item-ID не нужен. А «Правильная Вещь» — это не материал, поэтому остаётся Registrate-предметом `skufaddon:item_pravilnaya_vesh`.

### 9.2. Основные ID (адаптировано)

| Название | ID в `skuf-addon` | Категория |
|---|---|---|
| Жижняк | `skufaddon:jizhnyak` | материал (fluid) |
| Плотный жижняк | `skufaddon:dense_jizhnyak` | материал (fluid) |
| Нормисная пыль | `skufaddon:normie_dust` | материал (dust) |
| Нормисный осадок | `skufaddon:normie_residue` | материал (dust) |
| Скуфит | `skufaddon:skufit` ✅ | материал (ingot) |
| Похуит | `skufaddon:pokhuit` ✅ | материал (ingot) |
| Правильная материя | `skufaddon:correct_matter` | материал (gem) |
| Правильная Вещь | `skufaddon:item_pravilnaya_vesh` | Registrate item |
| Уральский изотоп | `skufaddon:ural_isotope` | материал (dust, radioactive) |
| Разрабская схема | `skufaddon:item_circuit_developer_unstable` | Registrate item |
| Пластина правильной мысли | `skufaddon:item_wafer_correct_thought` | Registrate item |
| Стабилизированный вайб | `skufaddon:stabilized_vibe` | материал (fluid) |
| Похуистический корпус | `skufaddon:casing_pohuit_reinforced` | Registrate block |
| Нормисный фильтр (расходник) | `skufaddon:item_normie_filter` | Registrate item |

> **Стабильность ID:** менять `mod_id`/имена материалов после релиза нельзя — иначе ломаются сейвы и квестбук. Имена закладываются один раз в `SkufMaterials`/`SkufItems`.

### 9.3. Кастомные ключи рецептов (важно для KubeJS-потребителей модпака)

Если завести кастомные `RecipeCapability` (например «давление тильта» как условие рецепта), их обязательно регистрировать через `registerRecipeKeys` в `SkufGTAddon` (закомментированный пример есть прямо в файле). Иначе KubeJS на стороне модпака будет вырезать такие рецепты.

## 10. Варианты для приватной и публичной версии

Сборка делается для группы друзей, поэтому локальные имена можно использовать жёстче. Но лучше заранее вести два слоя названий: **Приватное название** и **Публичный вариант**, чтобы при желании выложить сборку без переименования всей логики. В коде это решается тем, что внутренний ID латиницей стабилен, а отображаемое имя (lang / `langValue`) можно менять.

| Приватное название | Публичный вариант | Причина |
|---|---|---|
| Толстуха / Жирняк | Грузный мутант / плотная биомасса | Для публичного релиза мягче |
| Похуит | Апатит / Похуит | Можно оставить в приватной, публично стилизовать (ID `pokhuit` не трогаем) |
| Нормисная пыль | Энтропийная пыль | Если нужна англоязычная версия |
| Скуфит | Скуфит | Можно оставить как локальный минерал |
| Дядя Саид | Добрый Дядя | Реальное имя лучше скрыть публично |
| Арсенов дрейф | Пассивный дрейф | Имя оставить только в приватной версии |
| Тешкин рандом | Трикстер-рандомайзер | Имя оставить только в приватной версии |
| Аеро-ремонтник | Аварийный ремонтный верстак | Имя оставить только в приватной версии |
| Антизумерный реактор | Антиэнтропийный реактор | Для публичного тона мягче |
| Воркута-лайфстайл | Лайфстайл вечной мерзлоты | Для универсальности |

## 11. Баланс и дизайн-ограничения

### 11.1. Что нельзя ломать

- **Правильная Вещь** не должна стать обычной монетой. Это пропускной ресурс.
- **Вайб** не должен быть декоративным числом. Он должен реально менять стабильность или выходы (через `recipeModifier`).
- **Нормисная Энтропия** не должна быть просто наказанием. Игрок должен получать награды за риск.
- **Похуизм** не должен быть универсальным лучшим апгрейдом. Пусть даёт стабильность, но режет скорость или эффективность.
- **Жижняк** должен быть нужен долго, но не душить инвентарь.
- **Разрабские схемы** должны быть полезны даже с риском.
- **Руин** должен быть опционален, иначе он будет злить.

### 11.2. Как сделать это GregTech-овым

| Ошибка | Как исправить (в терминах `skuf-addon`) |
|---|---|
| Мемный предмет без функции | Дать ему место в цепочке рецептов (`SkufRecipes`) |
| Слишком лёгкий ресурс | Добавить побочные продукты и переработку |
| Слишком абстрактная механика | Привязать к машине/`recipeModifier`/`MachineTrait` |
| Лор отделён от производства | Делать квесты через рецепты и предметы-гейты |
| Всё доступно сразу | Разнести по тирам (`tiersBetween(...)`) |
| Нет инженерной боли | Ввести фильтры, обслуживание, отходы, требования к энергии |

## 15. Модуль `Дихотомия Пота и Угара`

### 15.1. Назначение модуля

`Дихотомия Пота и Угара` — это слой поверх GregTech-прогрессии, который превращает философский конфликт **«потеем / угараем / делаем вид, что не потеем»** в техническую систему фабрики.

В обычной экспертной сборке игрок видит перегрузки, ошибки логистики, нехватку ингредиентов, мигающие интерфейсы и аварийные звуки.  
В ArthurTech это переосмысляется как социально-психологическая драма завода: фабрика может **стараться скрытно**, публично показывать **0% пота**, гореть изнутри, игнорировать ошибки через кнопку **«Ваще похуй»**, а потом взорваться от накопленного тильта.

Основная формула:

```text
Не потеем публично
↓
Скрытно разгоняемся
↓
Жрём EU/t и ресурсы
↓
Делаем вид, что всё легко
↓
Ошибки копятся
↓
Ваще похуй
↓
Горящий пукан / детонация БП
```

Этот модуль должен быть не декоративным, а системным: он влияет на энергию, автокрафт, потери ресурсов, аварии, квесты и поздняя игра цели.

> **Реализация в `skuf-addon`:** это главный «не-KubeJS» слой, ради которого нужен Java-аддон. Технически он строится на: per-chunk `SavedData` (энтропия/вайб/скрытый тильт), `MachineTrait` на контроллерах (тильт, режимы линии), Forge tick-событиях и хуках остановки рецепта, а клиентский HUD/маскировка ошибок — через mixin (готовая точка входа `DummyMixin`). База модуля — материалы `sweat` ✅ и `puff_smoke` ✅, уже заведённые в шаблоне. В GTCEu уже есть система Hazard Zones (`machine/trait/hazard/`), которую удобно расширить под Нормисную энтропию вместо написания с нуля.

## 17. Энергетическая система: режимы «Угар» и «Пот»

### 17.1. Важная адаптация под GregTech

В исходном концепте режимы «Угар» и «Пот» могут звучать как замена стандартных напряжений LV/MV/HV. Для GregTech это ломало бы основу прогрессии, поэтому в ArthurTech они работают **не вместо тиров**, а **поверх тиров**.

```text
LV / MV / HV / EV / IV+
+
Режим линии: Угар / Пот / Не потеем / Ваще похуй
=
Реальное поведение фабрики
```

То есть у каждой линии остаётся напряжение, ампераж, EU/t, рецепты, параллельность и риск взрыва, но сверху появляется эмоционально-термодинамический режим.

> **Реализация:** режим линии — это enum-состояние на контроллере (`LineMode { UGAR, POT, NE_POTEEM, POHUI }`), который меняет `recipeModifier` (скорость/EU/потери) и скрытый расход EU/t. Хранится в данных машины; переключается через UI контроллера.

### 17.2. Линия «Угар» — Угарная автоматизация

**Смысл:** игрок строит как будто расслабленно. Кабели идут криво, трубы протянуты как попало, интерфейс не орёт, всё выглядит смешно и легко.

**Плюсы:**
- проще вход в автоматизацию;
- меньше требований к точности логистики;
- можно запускать кривые полуавтоматические линии;
- хорошо подходит для ранней/средней игры и приватного сервера.

**Минусы:**
- скрытый расход EU/t выше на 25–150%;
- часть материалов может уходить в `slag_ignore` и `zhizhnyak_loss`;
- при долгой работе растёт скрытый показатель Тильта;
- игрок может слишком поздно узнать, что линия уже полчаса ест ресурсы в никуда.

**GregTech-аналогия:** неэффективная, но рабочая цепочка, где игрок осознанно переплачивает ресурсами.

**Пример формулы (в `recipeModifier`/trait):**

```text
базовый_EUt * 1.4
+ 5% шанс: побочный_выход = zhizhnyak_loss
+ скрытый_тильт += длительность_рецепта / 200
```

### 17.3. Линия «Пот» — Оптимизация максимального пота

**Смысл:** линия идеально оптимизирована, тайминги выверены, буферы минимальны, КПД максимальный. Любая ошибка воспринимается как личное оскорбление завода.

**Плюсы:**
- +20–40% скорость;
- -10–25% расход материалов;
- +шанс получить редкий побочный продукт;
- лучше подходит для дорогих ресурсов: Уральский изотоп, Правильная материя, схемы.

**Минусы:**
- остановка из-за нехватки ингредиента вызывает резкий скачок Тильта;
- неправильный вход в шину может заблокировать интерфейс линии;
- аварийные звуки и чат-логи становятся агрессивными;
- если игрок включает «Ваще похуй» поверх режима «Пот», риск катастрофы резко растёт.

**GregTech-аналогия:** максимальный разгон, почти без буферов, высокая плотность EU/t, высокая цена ошибки.

**Пример формулы:**

```text
длительность * 0.75
стоимость_материалов * 0.95
if нет_входа:
    tilt += 25
if забит_выход:
    tilt += 40
```

### 17.4. Режим «Не потеем» — Расслабленный фасад

«Не потеем» — это не Угар и не Пот, а **визуальная маска** (client-side слой поверх режима линии).

Фабрика работает, возможно, на пределе, но все мониторы показывают:

```text
Пот: 0%
Статус: Полный угар
Ошибки: отсутствуют
Сложность: не обнаружена
```

**Эффекты режима:**
- скрывает анимации дыма, искр, тревожные звуки;
- маскирует красные маркеры на панели управления;
- понижает «психологическое давление» на игрока;
- повышает скрытый расход EU/t;
- включает скрытый разгон, чтобы система выглядела лёгкой.

**Цена:** реальная сложность никуда не исчезает. Она превращается в тильт.

## 18. Модуль аварийного игнорирования: «Ваще похуй»

### 18.1. Назначение

**Модуль Аварийного Игнорирования** — многоблочный контроллер для центрального пульта фабрики (класс `EmergencyIgnoranceMachine` в `machine/multiblock/`).

Он нужен не для ремонта. Он нужен, чтобы игрок мог нажать большую кнопку и временно жить в мире, где завод не сломан.

### 18.2. Структура мультиблока

**Название:** `Контроллер аварийного игнорирования` / `Модуль «Ваще похуй»`

**Тир:** HV → EV

**Компоненты:**
- 1x `Мейнфрейм «Ваще похуй»`
- 4x `Люк глушения ошибок`
- 4x `Шина стирания логов`
- 2x `Дробитель застрявших предметов`
- 2x `Люк тихой тревоги`
- 1x `Пукан-индикатор`
- 1x `Порт управления Мыпошко`
- корпус: `skufaddon:casing_pohuit_reinforced`

### 18.3. Активация

На центральном пульте появляется тумблер:

```text
[ ВАЩЕ ПОХУЙ ]
```

При активации:

1. отключаются сирены тревоги;
2. приглушаются звуки ломающихся механизмов;
3. скрываются красные маркеры поломок;
4. системные уведомления в чате заменяются нейтральными сообщениями;
5. логи ошибок стираются или складываются в `compressed_denial_log`;
6. зависшие предметы и жидкости в трубах перемалываются в `slag_ignore` и `zhizhnyak_loss`;
7. Тильт продолжает расти скрытно.

### 18.4. Пример сообщений

Публичный интерфейс:

```text
Фабрика: всё нормально.
Пот: 0%.
Угар: полный.
Ошибки: не обнаружены.
```

Скрытый лог, если его раскопать через «Разбор геймплея»:

```text
12 входных шин заблокировано.
7 крафтовых паттернов сломано.
4 конвейера заклинило.
213 предметов превращено в Жижняк Потерь.
Скрытый тильт: 83%.
```

### 18.5. Цена эскапизма

Главное правило:

```text
«Ваще похуй» не чинит завод. Оно только запрещает заводу жаловаться.
```

Пока режим активен:
- все застрявшие предметы постепенно превращаются в шлак;
- жидкости в забитых трубах превращаются в жижняк;
- шанс скрытого перегрева растёт;
- если игрок не выключает режим слишком долго, наступает катастрофа «Горящий пукан».

### 18.6. Баланс

Чтобы кнопка не стала имбой:

| Параметр | Рекомендация |
|---|---|
| Минимальный тир | HV |
| Первое появление в квестбуке | После Челябинского Провала |
| Максимальное безопасное время работы | 5–15 минут |
| Стоимость активации | Правильная Материя + Похуитовые платы |
| Скрытый штраф | Потери выхода + рост Тильта |
| Перезарядка | 30–60 минут игрового времени |
| Поздняя игра улучшение | Матрица Абсолютного Похуизма уменьшает потери, но не убирает их |

## 19. Термодинамика тильта: Пукан-индикатор и детонация БП

### 19.1. Основные параметры

> Все параметры хранятся в `MachineTrait` контроллера линии и/или в per-chunk `SavedData`; обновляются в tick и на событиях остановки рецепта.

| Параметр | Диапазон | Что означает |
|---|---:|---|
| `sweat_visible` | 0–100% | Видимый пот на интерфейсе |
| `sweat_hidden` | 0–100% | Реальное скрытое усилие линии |
| `ugar` | 0–100% | Уровень расслабленного фасада |
| `tilt_heat` | 0–100% | Накопленный эмоционально-технический перегрев |
| `denial_level` | 0–100% | Насколько сильно ошибки игнорируются |
| `pukan_indicator` | 0–100% | Итоговый риск «Горящего пукана» |

Формула риска:

```text
pukan_indicator =
tilt_heat * 0.55
+ sweat_hidden * 0.25
+ denial_level * 0.20
- sauna_cooling
- stabilized_vibe
```

### 19.2. Триггеры роста Тильта

> Технически вешаются на `onWorkingChanged`/события остановки рецепта и проверки входа/выхода машины.

| Событие | Рост Тильта |
|---|---:|
| Машина остановилась из-за нехватки ингредиентов | +5 |
| Входная шина забита не тем предметом | +10 |
| Выходной люк заполнен | +15 |
| Крафтовый паттерн AE2 сломался | +12 |
| Линия в режиме «Пот» остановилась | +25 |
| Игрок нажал «Ваще похуй» при активной ошибке | +20 |
| Линия Мыпошко скрыла ошибку | +8 в минуту |
| Сработал сценарий «Первый на лайне» | +30 |

### 19.3. Сценарий «Первый на лайне»

Триггер применяется к любой линии, которая:
- была важна для текущей автокрафт-цепочки;
- остановилась первой;
- остановила из-за себя весь нижестоящую цепочку;
- сделала это из-за банальной нехватки дешёвого предмета.

Пример:

```text
В линии процессоров кончился резистор.
Всё дерево крафта встало.
Контроллер пишет: «Первый на лайне».
Тильт +30.
```

### 19.4. Горящий пукан

Когда `pukan_indicator >= 100%`, начинается событие:

```text
СОБЫТИЕ: ГОРЯЩИЙ_ПУКАН
```

Эффекты:
1. все скрытые ошибки становятся видимыми;
2. статус «0% пота» ломается;
3. сирены включаются даже через глушитель;
4. в БП ЧПУ-станков плавятся конденсаторы;
5. часть кабелей превращается в `burnt_cable_debris`;
6. часть схем превращается в `charred_developer_circuit`;
7. МЭ-шаблоны, связанные с линией Мыпошко, требуют перепроверки;
8. игрок должен вручную пройти ремонтную цепочку.

### 19.5. Детонация БП

**Детонация БП** — это не всегда взрыв блока. Чтобы не делать механику слишком токсичной, есть три уровня (выбираются конфигом):

| Уровень | Название | Последствия |
|---|---|---|
| 1 | Плавление конденсатора | Машины линии останавливаются, нужен ремонт |
| 2 | Пробой энергосети | Кабели и энергохэтчи получают урон/заменяются мусором |
| 3 | Полное выгорание зоны | Весь промышленный сегмент уходит в оффлайн до ручного восстановления |

Для приватной версии можно сделать уровень 3 жёстким. Для публичной версии лучше оставить только уровень 1–2.

### 19.6. Ремонт после катастрофы

Ремонтная цепочка:

```text
burnt_cable_debris
→ очистка в Химической ванне
→ медно-угольный остаток
→ переплавка
→ repaired_cable_core
```

```text
charred_developer_circuit
→ вскрытие в Разборщике схем
→ cracked_logic_piece
→ пайка со Стабилизированным вайбом
→ recovered_developer_circuit
```

```text
melted_capacitor
→ Вакуумный морозильник
→ cracked_capacitor_shell
→ сборка с Электролитным гелем
→ replacement_psu_capacitor
```

Квестовый текст:

> «Ты делал вид, что не потел. Завод тоже делал вид. Теперь вы оба стоите среди дыма и чините БП.»

## 20. Автоматизация Мыпошко

### 20.1. Что такое методика Мыпошко

**Мыпошко** — это стиль автоматизации, где вместо идеальной логики используется набор костылей, скрытых маршрутов, временных буферов и фасадной уверенности.

Она не плохая. Она просто честно признаёт, что завод часто строится не как учебник, а как живой организм: где-то труба не туда, где-то интерфейс забыт, где-то паттерн отработал случайно.

### 20.2. Игровой смысл

Мыпошко даёт игроку возможность строить быстрее и смешнее, но за это он платит:
- скрытыми ошибками;
- повышенным расходом энергии;
- накоплением тильта;
- риском выгорания зоны;
- необходимостью периодического «Разбора геймплея».

### 20.3. Блоки методики Мыпошко

| Блок | Тир | Роль |
|---|---|---|
| `Логический порт Мыпошко` | MV | Подключает линию к алгоритму |
| `Люк временного буфера` | MV | Скрывает застревания предметов |
| `Шина отрицания` | HV | Игнорирует локальную ошибку |
| `Модуль оправдания паттерна` | HV | Помечает сломанный паттерн как «нормальный» |
| `Мейнфрейм «Ваще похуй»` | HV/EV | Глобально активирует игнор |
| `Терминал разбора геймплея` | MV/HV | Позволяет всё-таки понять, что случилось |

### 20.4. Правило баланса

Мыпошко должно быть **соблазнительным**, но опасным:

```text
Без Мыпошко:
медленнее, скучнее, стабильнее.

С Мыпошко:
быстрее, смешнее, дешевле на старте,
но дороже в ремонте и опаснее в поздняя игра.
```

## 21. «Разбор геймплея»: автоматизированный аудит ошибок

### 21.1. Назначение

`Терминал разбора геймплея` / **Блок «Пошёл Разбор Геймплея»** — специальный диагностический компьютер для МЭ-сети и GregTech-линий.

Он нужен, чтобы игрок понимал:
- почему встал автокрафт;
- где застрял предмет;
- какая машина первая умерла на линии;
- какие ошибки скрыты режимом «Ваще похуй»;
- сколько ресурсов уже превращено в шлак.

### 21.2. Подключение

Терминал подключается к:
- МЭ-контроллеру / поставщикам паттернов;
- GT-входным/выходным шинам;
- энергетическим хэтчам;
- Логическим портам Мыпошко;
- Модулю «Ваще похуй»;
- Пукан-индикатору.

### 21.3. Режимы работы

| Режим | Описание | Цена |
|---|---|---|
| Быстрый Разбор | Показывает одну главную ошибку | Низкий EU/t |
| Полный Разбор | Печатает дерево причин остановки | Высокий EU/t |
| Жёсткий Разбор | Вскрывает скрытые ошибки режима «Ваще похуй» | Рост Тильта |
| Разбор Тиммейтов | Показывает, какой сегмент фабрики «не потеет» | Риск депрессии механизмов |

### 21.4. Эффект давления

Когда игрок открывает полный лог ошибок, фабрика получает психологический удар:

```text
статус: Механизмы плачут
скорость_переработки: -50%
длительность: 3–10 минут
побочка: technical_tears
```

Это не наказание ради наказания. Это художественное отражение ситуации: когда всем указывают на ошибки, никто не хочет работать быстрее.

### 21.5. Как снять дебафф

- исправить хотя бы одну корневую причину;
- переписать сломанный паттерн;
- заменить забитую входную шину;
- пустить `stabilized_vibe`;
- построить рядом `Модуль комфорта Дяди Саида`.

## 22. Стабилизатор «Сауна Егора»

### 22.1. Смысл

**Сауна Егора** — огромный жидкостный радиатор, который поглощает тепловой тильт фабрики (класс `SaunaEgoraMachine`, мультиблок-сток тильта в радиусе).

Философская формула:

```text
В сауне не потеет никогда.
Значит, сауна — абсолютный отрицатель пота.
```

### 22.2. Роль в прогрессии

**Тир:** EV / IV

**Почему не раньше:** если дать игроку полное снятие тильта на MV/HV, «Ваще похуй» станет бесплатной кнопкой. Сауна должна быть мощной, дорогой и требовать отдельной инфраструктуры.

### 22.3. Структура мультиблока

**Размер:** 7x7x7 или 9x9x9  
**Компоненты:**
- `Корпус поглотителя жара сауны`
- `Люк конденсации пара`
- `Вайб-охладительная катушка`
- `Входной люк технических слёз`
- `Выхлопной люк горячего тильта`
- `Ядро Егора`
- минимум 16 водяных/паровых труб
- декоративные лавки, если хочется вайба

### 22.4. Рецептурный цикл

```text
tilt_heat + вода + stabilized_vibe
→ warm_vibe_steam + technical_tears
```

```text
warm_vibe_steam
→ конденсатор
→ calm_вода + residual_ugar
```

```text
technical_tears + pohuit_dust
→ coolant_of_denial
```

### 22.5. Эффекты

| Эффект | Значение |
|---|---|
| Поглощение Тильта | -1…-5 тильт/тик в радиусе |
| Безопасный «Не потеем» | снижает цену скрытого разгона |
| Буфер перед «Горящим пуканом» | даёт 30–60 секунд льготное окно |
| Побочный ресурс | Технические слёзы |
| Риск | если не отводить пар, сама Сауна вызывает влажный руин |

## 23. Эндгейм-продукты: Лирика в Падике и Деревенский Покой

### 23.1. Капсула «Лирика в Падике»

**Важно для реализации:** это должен быть полностью вымышленный внутриигровой предмет. Не использовать реальные препараты, реальные дозировки и реальные инструкции.

**Смысл:** временный стазис, абсолютное игнорирование раздражителей, лагов, мобов и тильта.

**Тир:** IV+ / LuV

**Тип:** расходник / капсула / аварийный предмет стазиса (`skufaddon:item_lyrika_v_padike`)

**Рецептурный образ:**

```text
stabilized_vibe
+ technical_tears
+ padik_noble_gas
+ dense_jizhnyak
+ correct_matter_microcapsule
→ capsule_lyrika_v_padike
```

**Эффекты:**
- игрок входит в `absolute_stasis` на 30–180 секунд;
- урон по игроку сильно снижается или отключается;
- тильт линии вокруг игрока временно замораживается;
- интерфейс показывает: `Всё нормально. Потом разберёмся.`;
- весь активный автокрафт не ускоряется и не чинится.

**Цена:**
- после выхода из стазиса игрок получает `post_padik_disorientation`;
- если применить во время «Горящего пукана», катастрофа не отменяется — она просто ждёт окончания стазиса;
- предмет дорогой и не должен заменять нормальный ремонт.

**Квестовый текст:**

> «Это не решение проблемы. Это возможность 90 секунд не быть участником проблемы.»

### 23.2. Сингулярность «Деревенский Покой»

**Смысл:** настоящий финал ArthurTech — не бесконечный рост завода, а возможность перестать потеть вообще.

Это не просто Avaritia-стиль «скрафти бесконечность». Это философский финал: игрок строит настолько сложную фабрику, что получает право отключить фабрику.

**Тир:** Эндгейм / финал

**Тип:** сингулярность / ключ измерения / победный предмет

**Требования:**
- 64x Абсолютный Похуит;
- 16x Правильная Вещь;
- 8x Нормисная Сингулярность;
- 1x Артурийский мейнфрейм;
- 1x Сауна Егора в стабильном режиме;
- 1x очищенный Челябинский Провал;
- глобальная энтропия ниже 10%;
- ни одного активного «Ваще похуй» в момент запуска.

**Активация:**

```text
singularity_derevenskiy_pokoy
→ открывает_измерение: ПГТ / Деревня
```

### 23.3. Измерение ПГТ / Деревня

**Характеристики:**
- нет необходимости потеть;
- машины не взрываются;
- ресурсы генерируются пассивно, но медленно;
- нет нормисной энтропии;
- нет агрессивного автокрафта;
- НПС «Добрые дяди» дают квесты на бытовой вайб;
- финальная музыка — тихая, без сирен.

**Философский смысл:**

```text
GregTech довёл тебя до предела.
ArthurTech разрешает уйти в ПГТ.
```

> **Реализация:** кастомное измерение — самый дорогой и опциональный блок. Технически удобнее делать датапаком измерения модпака + предмет-ключ из аддона, чем полноценной dimension-логикой в самом аддоне.

**Квестовый текст:**

> «Ты построил завод, который мог производить всё. Теперь докажи, что можешь его выключить.»

## 27. Баланс: как не сломать сборку

### 27.1. «Ваще похуй» не должно быть repair button

Запрещено:

```text
Нажал кнопку → завод починился.
```

Правильно:

```text
Нажал кнопку → завод перестал жаловаться.
Застрявшие ресурсы умерли.
Тильт вырос.
Через время случилась катастрофа.
```

### 27.2. «Не потеем» не должно быть бесплатным разгоном

Любой скрытый разгон обязан иметь цену:
- EU/t;
- охлаждение;
- потеря output;
- рост тильта;
- повышенный шанс катастрофы;
- необходимость в Сауне Егора.

### 27.3. «Пот» должен быть полезен, но токсичен

Режим Пот — это для дорогих цепочек, где игрок готов контролировать процесс.

Он не должен быть всегда лучшим. Он должен быть:
- быстрым;
- эффективным;
- нервным;
- опасным при ошибке.

### 27.4. «Угар» должен быть удобным, но грязным

Режим Угар должен быть:
- проще;
- смешнее;
- менее точным;
- с заметными потерями;
- безопаснее для психики, но хуже по КПД.

### 27.5. Сауна Егора должна быть дорогой

Если она дешёвая, вся система тильта исчезает.

Минимальные требования:
- EV/IV компоненты;
- много воды/пара;
- отдельный контур охлаждения;
- стабильный вайб;
- место под большой мультиблок.

- фасад 0% пота.
- скрытый расход EU/t.

MV:
- Мыпошко.
- Разбор геймплея.

## 31. Соответствие best practices разработки GregTech-аддонов (июнь 2026)

> Раздел добавлен по итогам сверки концепции с актуальным API GregTech CEu Modern: официальная документация GTM, DeepWiki по исходникам (индекс 14.01.2026), README официального шаблона аддона (push 19.12.2025) и референс-аддоны GTCA / MoniLabs.

### 31.0. Вердикт

**Концепция рабочая — фундаментальных блокеров нет.** Все ключевые механики «Дихотомии Пота и Угара» ложатся 1-в-1 на штатные системы GTCEu Modern, а не требуют хаков:

- тильт / нормисная энтропия / режимы линии → кастомный `recipeModifier` + annotation-managed sync/save поля;
- контроллеры (Мыпошко, «Ваще похуй», Сауна Егора) → Java-классы на `MultiblockMachineBuilder`;
- материалы (Жижняк, Скуфит ✅, Похуит ✅) → `Material.Builder` + `TagPrefix`.

**Именно эта не-KubeJS логика и оправдывает Java-аддон** — на одних серверных KJS-скриптах персистентное состояние машин, кастомные трейты и контроллеры не сделать. Требуются не переделки, а 6 уточнений до «production-correct».

### 31.1. Версия — зафиксировать и не прыгать

На июнь 2026 GTCEu Modern активно развивается в двух ветках: **1.20.1-8.0.0 SNAPSHOT** и **1.21-8.0.0 SNAPSHOT (NeoForge)**. `skuf-addon` стоит на Forge 1.20.1 / GTCEu 7.4.0.

- **Рекомендация:** остаться на **1.20.1** — под неё официальный шаблон, оба референс-аддона (GTCA, MoniLabs) и большинство модпаков.
- Жёстко прописать точную версию GTCEu в `gradle.properties` и не смешивать миграцию на 1.21 с MVP — это отдельный риск и отдельный этап.

### 31.2. Хранение состояния — annotation-managed sync/save (ключевое уточнение)

Ранние формулировки концепции («`MachineTrait` + per-chunk `SavedData`») были расплывчаты. Актуальный best practice GTCEu Modern — **annotation-driven sync/save** (GTM ушёл от LDLib SyncData):

- Состояние машины (`tilt_heat`, `LineMode`, `vibe`) → поля с **`@Persisted`** / **`@DescSynced`** в `ManagedFieldHolder`, привязка через **`attachPersistentTrait(...)`** — а **не** ручной NBT.
- Глобальная **Нормисная энтропия** (на мир/чанк) → остаётся Forge/Neo `SavedData` / Capability — это корректно.
- ⚠️ **Мультиплеер:** всё, что показывается в HUD (тильт, маскировка), обязано быть **`@DescSynced`**, иначе на выделенном сервере клиент состояние не увидит.

### 31.3. Гейты и остановка линий — recipe modifier (подтверждено API)

Остановка/ускорение по тильту, переключение режимов линии и гейт «Правильная Вещь» реализуются штатным `recipeModifier`:

- `ModifierFunction.NULL` — остановить рецепт; `ModifierFunction.IDENTITY` — запустить;
- модификация EU/duration для бонусов/штрафов режимов;
- `recipe.data.getInt("...")` — кастомные требования рецепта (как `RequiredTemp` у EBF).

Ничего изобретать не нужно — это тот же механизм, что у температурных мультиблоков.

### 31.4. Баланс — в config, не в хардкод

Числа (скрытый EU/t по режимам, скорость роста тильта, пороги событий, коэффициенты пукан-формулы `0.55 / 0.25 / 0.20`) вынести в **config-систему GTCEu**, чтобы балансить сборку без перекомпиляции. Сейчас в концепции они зашиты в формулы — для тюнинга модпака этого мало.

### 31.5. Mixin'ы — минимизировать

Маскировка ошибок и HUD через mixin (точка входа `DummyMixin`) — рабочий, но самый хрупкий слой: **именно mixin'ы чаще всего ломаются при апдейтах GTCEu**. Где возможно — использовать штатные точки (LDLib-виджеты, machine UI, overlay renderer); mixin — только там, где API объективно не хватает. Меньше mixin'ов = легче пережить переход на 8.0.0.

### 31.6. Производительность и JEI/EMI

- **Не тикать каждую машину каждый тик.** Глобальные события (волны энтропии/зумеризации) и накопление тильта — через `ITickSubscription` с интервалом (раз в 20–40 тиков), иначе лаги на больших фабриках.
- Кастомные `recipe type` обязательно с **`.category()`**, иконкой и **`.setProgressBar(...)`** — иначе рецепты не отобразятся в JEI/EMI.

### 31.7. Процесс и инструментарий (из README шаблона)

- **Java обязателен**; официальной документации по аддонам нет → референс **GTCA** (`github.com/mordgren/GTCA`) и **MoniLabs** (`github.com/NegaNote/MoniLabs`).
- Шаблон поставляется со **Spotless** — гонять `spotlessApply` перед коммитом (единый код-стайл).
- Вопросы по API — **GregTech CEu Discord**.
