# Промпт: генерация идей для ArthurTech

Рамка для любой новой механики, предмета, блока, мультиблока или квеста. Применять **до** записи в roadmap.md и Linear.

---

## Обязательное чтение

Перед генерацией прочитать:

1. **[philosophy.md](philosophy.md)** — тон и смысл. Мир деградирует, спасение в цепочке рецептов, а не в красоте.
2. **[concept.md](concept.md)** — механики (§17 режимы линии, §18 «Ваще похуй», §19 термодинамика тильта, §20 Мыпошко, §21 Разбор Геймплея).
3. **[roadmap.md](roadmap.md)** — **§1** (что реально в коде), **§6** (орфаны), **§13** (геймплейный аудит, принятые изменения A+/Б1/C).
4. **[logic.md](logic.md)** — текущая архитектура кода.

**Приоритет при расхождении:** код > roadmap.md > concept.md > philosophy.md. В concept.md многое помечено «есть», хотя в коде отсутствует.

## Пять фильтров

Идея проходит **только если проходит все пять**. Провал любого — идея отбрасывается или переформулируется.

### Фильтр 1. Не переименование

Отбросить, если необычность идеи держится на названии, а механика — стандартный GregTech или копия существующей.

Проверка: **опиши идею, заменив все проектные названия на нейтральные.** Осталось что-то интересное?

- ❌ «Похуит-конденсатор снижает требования к обслуживанию» → это capacitor, снижающий maintenance. Уже есть в GTCEu.
- ✅ «Конденсатор поднимает порог тильта, при котором машину рвёт; стек конденсаторов = ставка: +скорость, +шанс сгорания» → выбор риск/награда, которого в GT нет.

Отдельно: **не дублировать решённое в GTCEu.** Батареи, лазеры, cleanroom, maintenance hatch уже существуют. Своя версия того же = шум.

### Фильтр 2. Замкнутость

У каждого предмета, жидкости, блока обязан быть **источник И потребитель И причина взаимодействовать**.

Третье — главное. Роадмап §13 показал: предметы замкнуты почти везде, но игрок не имеет *причины* трогать половину систем.

- Предмет производится и никуда не идёт → орфан (§6.3), не добавлять
- Предмет производится, потребляется, но игрок может пройти игру мимо → мёртвая ветка
- Идея закрывает существующий орфан → **бонус, приоритет вверх**

Исключение: фан-контент (пиво и подобное) — явно помечать как фан, не встраивать в прогрессию.

### Фильтр 3. Читаемость для новичка

Целевой игрок: **знаком с лором проекта частично, в GregTech играл, в этот аддон — нет.**

- Механика объясняется одним предложением без отсылки к внутренним мемам
- Причинно-следственная связь видна **в момент события**, а не постфактум. Игрок должен понять, *что* он сделал не так, немедленно
- Название смешное, работа — понятная. Юмор в обёртке, не в механике
- Ничего невидимого, что бьёт по игроку. Скрытая механика допустима, только если у игрока есть инструмент её увидеть

Проверка: **что игрок подумает в первые 10 секунд после срабатывания?** Если «что это было» — переделать.

### Фильтр 4. Реализуемость в текущем стеке

Стек: Minecraft 1.20.1 Forge, Java 17, GTCEu 7.5.1, LDLib 1.0.40.b, GTRegistrate.

Есть и работает:
- `SimpleTieredMachine` + `RecipeLogic` (тильт живёт здесь)
- `WorkableElectricMultiblockMachine` + паттерны
- `@Persisted` / `@DescSynced` через `ManagedFieldHolder` — синхронизация полей машины
- `SavedData` — per-chunk / глобальное состояние
- `subscribeServerTick` — тики машины
- AABB-зона вокруг структуры (`ChelyabinskProvalMachine`)
- Provider/Receiver-привязка при сборке мультиблока (`ISaunaProvider`)
- Конфиг (`SkufBalanceConfig`), Jade-интеграция, `observer/` (голос Артура)

Дорого / рискованно — требует явного обоснования:
- Mixin в чужой код
- Кастомный HUD-рендер
- Обход топологии автокрафта / AE2-интеграция
- Новое измерение

**Разрушение блоков в мире — разрешено** (реш. §13.7.5): проект для своих, публичный сервер с приватами не планируется, конфликта с защитой территорий не будет. Условия:
- `level.destroyBlock` + ручной дроп, без миксинов
- **дроп обязателен и чиним** — ничего не исчезает безвозвратно
- **конфиг отключения обязателен**, отдельно от механики, которая это вызывает

Указывать: **какие классы трогаем, какие поля добавляем.**

### Фильтр 5. Соблазн, а не налог

Из roadmap.md §13.3 — главный вывод аудита.

Механика обязана давать игроку **выбор с обеих сторон**:

- ❌ Растёт само, игрок терпит → налог. Это GTNH pollution с мемным именем
- ❌ Чистый штраф без апсайда → игрок обходит или игнорирует
- ✅ Игрок сам решает включить ради выгоды, платит за провал → ставка
- ✅ Инструмент, поднимающий потолок риска (позволяет жадничать безопаснее)

Проверка: **зачем игроку это трогать, если можно не трогать?** Нет ответа → механика мертва.

Отдельно про рутину: расходник в каждой машине при сотне машин = логистический ад. GTCEu не зря повесил maintenance только на мультиблоки. Если идея требует обслуживания — привязывать к **добровольному разгону**, а не к самому факту работы.

## Формат ответа

Для каждой идеи:

```
### Название

**Что делает:** одно предложение, механически, без мемов.

**Практическая логика:** зачем игроку это трогать. Какой выбор появляется.

**Замкнутость:** источник → потребитель → причина. Какие орфаны закрывает.

**Опыт новичка:** что игрок видит и понимает в момент срабатывания.

**Реализация:** какие классы/поля, что из стека используется. Оценка сложности.

**Фильтры:** 1 ✅/❌ · 2 ✅/❌ · 3 ✅/❌ · 4 ✅/❌ · 5 ✅/❌
```

Плюс отдельным блоком: **что я сознательно отбросил и почему.** Отброшенные идеи ценны — они фиксируют, что вариант рассмотрен.

## Чего не делать

- Не добавлять предмет, потому что он есть в concept.md. Док писался до кода
- Не плодить квесты «на объём». Квест обязан вести к механике, которую игрок и так хотел
- Не строить на несуществующем фундаменте. roadmap.md §13.4: эндгейм-лестница не начинается, пока не готов стек идентичности §13.3
- Не решать одну задачу двумя машинами. Если новая машина делает то же, что существующая — развести по функции или отбросить
- Не предлагать «настраивается конфигом» вместо дизайн-решения. Конфиг — для баланса, не для выбора механики
